# Editing this presentation

The talk is a browser presentation with 17 slides. It ends with the research proposal. The phone app finale was removed. You can edit the presentation with Claude Code, Claude Desktop with folder access, Codex, or another assistant that can edit a local repository.

## First session

1. Ask Christopher for collaborator access to the GitHub repository if you need to push changes. Otherwise, make a fork and send a pull request.
2. Install Node.js 22.13 or newer. Clone the repository with GitHub Desktop, or use the terminal commands below.
3. Open the cloned folder in your coding assistant. Ask it to read `AGENTS.md` and this guide first.

```sh
git clone https://github.com/cjbarrie/nyu-sociology-ai-research.git
cd nyu-sociology-ai-research
npm ci
npm run dev
```

The terminal prints a local URL. Open that URL in your browser. Keep the terminal running while editing; the preview reloads as files change. You do not need an OpenAI key, Claude key, or Sites account to run the presentation. Your assistant may require its own subscription.

If using ordinary Claude chat without folder access, upload the relevant files from the table below and ask for edited files back. Download those files into the same locations in your clone. A chat response alone does not update the presentation.

## Where to edit

| Change | File |
|---|---|
| Most slides, order, navigation, file links and dialogs | `app/page.tsx` |
| Opening research slides and agent diagram | `app/opening.tsx` |
| Slide typography, spacing and colors | `app/globals.css` |
| Formatted evidence, source reviews and walkthrough pages | `public/workshop/` |
| Research sources and source-check records | `research/` |
| Downloadable PDFs, bibliography and recordings | `public/artifacts/` |
| PDF slide backup and timed notes generator | `scripts/presentation_pdf.py` |
| LaTeX research proposal | `research/protocol/memo.tex` |
| Deployment | `.github/workflows/pages.yml` |

Browser slides and PDF slides have separate source files. Ask the assistant to update both when slide content changes. `research/speaker-notes.md` and its public copy are generated by the PDF script; edit the notes in that script to keep changes after regeneration. The current PDF generator uses macOS Arial and Georgia; on other systems ask the assistant to configure equivalent installed fonts. The browser-only build works on macOS, Windows and Linux.

## Prompts you can paste

**Make a small edit**

> Read AGENTS.md and docs/CO_PRESENTER.md. Create an editing branch. On the slide titled “Guided collaboration”, change [describe the change]. Keep the academic tone and existing layout. Update the corresponding PDF slide source and notes. Run the build, then tell me which files changed and what I should inspect in the browser. Do not merge until I have reviewed it.

**Revise an opening research slide**

> Update the slide titled [title] using this paper: [link or attachment]. Check the primary source, publication status and the outcome actually measured. Keep the citation and screenshot clickable. Do not turn a correlation or simulation into a causal result. Preserve the distinction between illustrated workflows and recorded execution. Update the PDF source and notes too.

**Prepare a reviewed change for publication**

> Review the diff for broken links, unsupported claims and accidental changes. Run npm run build. Check the GitHub Pages project-path preparation. Commit the edits on this branch and open a pull request describing what changed and how it was checked. Do not include credentials, downloaded source papers or local build caches.

## Review and publish

Use a separate branch for edits. GitHub Desktop can create the branch, show the diff, commit and push without terminal commands. Open a pull request and have the other presenter review it. The build runs on pull requests; merging into `main` publishes automatically through GitHub Actions. Check the **Actions** tab for the green deployment result before presenting.

Preview the changed slides, open the evidence and PDF dialogs, and follow the links you will use live. Arrow keys move slides; N opens notes; F enters full screen. Use slide titles when requesting changes because numbering may move.

The GitHub Pages site and the older private ChatGPT-hosted site are separate deployments. Merging here updates GitHub Pages only. Use the GitHub Pages link when sharing the current version with colleagues.

## PDF and research updates

For PDF slides install Python dependencies with `pip install reportlab pillow pypdf`, then run `python scripts/presentation_pdf.py`. Commit the regenerated `public/artifacts/presentation.pdf` and both notes files. On non-macOS machines configure font paths first. For the research proposal, a TeX Live installation is needed; run `latexmk -pdf -cd research/protocol/memo.tex`, then copy the resulting PDF to `public/artifacts/study-protocol.pdf`.

`npm run build` does not regenerate research PDFs. Do not claim those were updated unless you regenerated and inspected them. Avoid running all research-generation scripts for a wording change: some rebuild multiple historical artifacts. Ask the assistant to inspect the relevant script before running it.
